## Overview

RecompAI is an AI-powered body recomposition coaching platform that combines meal tracking, supplement management, and personalized coaching into a single application. The goal is to replace the fragmented stack of calorie counters, supplement reminders, and generic fitness apps with one platform that actually understands your full health context.

What makes RecompAI different from existing trackers is multi-modal input. Instead of tediously searching a food database and logging every ingredient, users can snap a photo of their plate, describe a meal in a voice memo, or type a quick text description. Llama 3.2 Vision analyzes the input and estimates macronutrients automatically, turning a 2-minute logging chore into a 5-second interaction.

The AI coaching layer ties everything together. Because the platform has full context on your meals, supplements, and progress trends, coaching conversations are specific and actionable -- not the generic advice you get from ChatGPT prompts. Weekly automated email summaries surface trends and insights that would be invisible in day-to-day tracking.

## Tech Stack Breakdown

### Infrastructure

- **Cloudflare Workers** -- Handles all API routes, AI inference orchestration, and server-side rendering. The stateless edge model keeps response times fast regardless of user location.
- **D1 (SQLite at Edge)** -- Stores user profiles, meal logs, supplement protocols, coaching conversation history, and weekly summary data. Schema designed for efficient time-series queries on meal and supplement data.
- **R2 (Object Storage)** -- Stores meal photos uploaded by users. Images are processed by Workers AI for macro estimation before the thumbnail is stored for the meal history UI.

### Frontend

- **React 19** -- Client-side UI with server components for initial page loads. The meal logging interface needs to be responsive and fast -- React's concurrent features handle photo uploads and AI processing feedback without blocking the UI.
- **Capacitor** -- Wraps the web application in a native iOS shell. Provides access to the device camera for meal photos, microphone for voice input, and push notifications for supplement reminders. One codebase serves both web and native.

### AI & Search

- **Workers AI (Llama 3.2 Vision)** -- The multi-modal model powers meal analysis from photos. Given an image of a plate of food, it identifies individual items, estimates portion sizes, and calculates approximate macronutrient values. Also handles text-based meal descriptions and voice transcription analysis.
- **Vectorize** -- Cloudflare's vector database stores embeddings of meals, coaching conversations, and supplement protocols. Enables semantic search over meal history ("when did I last eat salmon?") and gives the coaching AI access to relevant historical context during conversations.

### Communication

- **Email Summaries** -- Automated weekly digests compile meal trends, supplement adherence rates, macro averages, and coaching insights. Generated by Workers AI from structured data and delivered via scheduled Workers.

## Key Features

- **Multi-Modal Meal Tracking** -- Log meals via photo (AI vision analysis), voice memo (transcription + parsing), or text description. AI estimates macros automatically, eliminating manual food database searches.
- **Supplement Protocol Management** -- Define supplement stacks with dose escalation schedules, track daily adherence, and receive reminders. The system understands cycling protocols and loading phases.
- **AI Coaching Conversations** -- Context-aware coaching that references your actual meal history, supplement protocols, and progress trends. Not generic advice -- specific recommendations based on your data.
- **Semantic Meal History Search** -- Find past meals by description, not just date. "Show me high-protein dinners from last week" works because meals are indexed by vector embeddings.
- **Weekly Automated Summaries** -- Email digests with macro trends, adherence rates, notable patterns, and AI-generated insights about your progress.
- **Native iOS App** -- Full native experience via Capacitor with camera integration, push notifications, and offline meal draft support.

## Challenges & Solutions

### Vision Model Accuracy for Food Recognition

**Problem:** Food recognition from photos is inherently ambiguous. Portion sizes are hard to estimate from a single image, and visually similar foods can have very different macro profiles (cauliflower rice vs. white rice, for example).

**Approach:** Rather than treating the AI estimate as ground truth, the system presents its analysis as an editable suggestion. Users see "Looks like grilled chicken breast (~6oz), brown rice (~1 cup), steamed broccoli (~1 cup)" and can adjust quantities or swap items. Over time, the model's accuracy for a specific user improves because correction patterns are stored and referenced.

**Solution:** The correction-loop approach means the AI gets more accurate for each user's typical meals. A user who eats the same breakfast regularly will see near-perfect estimates after a few corrections. The UX communicates uncertainty honestly -- confidence scores are shown, and the edit interface is frictionless.

### Conversation Context Management at Scale

**Problem:** AI coaching conversations need access to weeks or months of meal and supplement history to give specific advice. But sending an entire user history with every chat message would blow past context windows and add unacceptable latency.

**Approach:** Used Vectorize to create a retrieval-augmented generation (RAG) pipeline. When a user sends a coaching message, the system embeds the query, retrieves the most relevant meal logs, supplement records, and previous coaching exchanges, then constructs a focused context window for the AI.

**Solution:** Coaching responses reference specific meals and patterns from the user's history without requiring the full history in context. A user asking "Why am I so tired in the afternoons?" gets an answer that considers their recent lunch patterns, caffeine timing, and sleep-related supplement protocols -- not a generic "try sleeping more" response.

### Native App Bridge with Web-First Architecture

**Problem:** The platform is web-first, but meal photo logging is dramatically better as a native experience. Camera access, photo library integration, and push notifications for supplement reminders all need native capabilities.

**Approach:** Chose Capacitor over React Native to maintain a single web codebase. Native plugins handle camera, filesystem, and push notification access. The web app detects its runtime environment and adapts the UI accordingly -- native users see a camera button in the meal logger, web users see a file upload.

**Solution:** One codebase deploys to both web and iOS with platform-appropriate UX. Camera-to-AI analysis takes under 3 seconds on device. Push notifications drive supplement adherence rates significantly higher than web-only reminders.
