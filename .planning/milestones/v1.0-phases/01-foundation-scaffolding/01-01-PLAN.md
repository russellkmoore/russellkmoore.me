    6. NOTE on D-01 (adapter): Research found that `@astrojs/cloudflare` is designed for on-demand rendering (SSR) only and does NOT support `output: "static"`. Official Astro docs: "If you're using Astro as a static site builder, you don't need an adapter." Skipping the adapter for Phase 1 per research recommendation. The adapter can be added in a 2-minute change when switching to server/hybrid output. This is a research-informed deviation from D-01.

    7. Create `astro.config.mjs` with this exact content:
       ```javascript
       import { defineConfig } from "astro/config";
       import tailwindcss from "@tailwindcss/vite";
       import sitemap from "@astrojs/sitemap";

       export default defineConfig({
         site: "https://russellkmoore.me",
         output: "static",
         integrations: [sitemap()],
         vite: {
           plugins: [tailwindcss()],
         },
       });
       ```
       No adapter import. No @astrojs/tailwind. No tailwind.config.js. No postcss.config.js. Per D-03 and D-06.

    8. Create `tsconfig.json`:
       ```json
       {
         "extends": "astro/tsconfigs/strict"
       }
       ```

    9. Set npm scripts in `package.json`:
       ```json
       {
         "scripts": {
           "dev": "astro dev",
           "build": "astro build",
           "preview": "astro preview",
           "deploy": "astro build && wrangler deploy",
           "check": "astro check"
         }
       }
       ```
       Per D-02 and INFRA-07.

    10. Create `wrangler.toml` per D-02:

        CRITICAL: `prettier-plugin-tailwindcss` MUST be last in the plugins array.

    12. Create a minimal `public/favicon.svg` -- a simple violet-accented placeholder SVG (a geometric shape using #7c3aed).

  <name>Task 2: Create dark theme CSS, Layout with FOUC prevention, and minimal index page</name>
  <files>src/styles/global.css, src/layouts/Layout.astro, src/pages/index.astro</files>
  <read_first>
    astro.config.mjs (verify Tailwind vite plugin is configured),
    .planning/phases/01-foundation-scaffolding/01-RESEARCH.md (Pattern 2: Layout, Pattern 3: Tailwind v4 CSS config, Pitfall 1: dark mode, Pitfall 3: FOUC, Pitfall 4: font CLS),
    .planning/phases/01-foundation-scaffolding/01-UI-SPEC.md (Color tokens, Typography, Dark Theme Implementation, Spacing Scale)
  </read_first>
  <action>
    Create the three source files that establish the visual foundation.

    1. Create `src/styles/global.css` with this exact content:
       ```css
       @import "tailwindcss";

       @custom-variant dark (&:where(.dark, .dark *));

       @theme {
         --color-background: #0a0a0f;
         --color-foreground: #f5f5f5;
         --color-muted: #a1a1aa;
         --color-accent: #7c3aed;
         --color-accent-hover: #8b5cf6;
         --font-sans: "Geist Variable", "Inter", system-ui, sans-serif;
       }
       ```
       CRITICAL: The `@custom-variant dark` line MUST be present. Without it, ALL `dark:` prefixed Tailwind classes silently produce no CSS. This is Pitfall 1 from research.
       Per D-06 (CSS-based config, no JS), D-09 (theme tokens), D-10/D-11 (font stack).

    2. Create `src/layouts/Layout.astro` with this exact content:
       ```astro
       ---
       import "@fontsource-variable/geist";
       import "@fontsource/inter/400.css";
       import "@fontsource/inter/500.css";
       import "@fontsource/inter/600.css";
       import "@fontsource/inter/700.css";
       import "../styles/global.css";

       interface Props {
         title: string;
         description?: string;
       }

       const { title, description = "Russell Moore — Engineering Leader & Builder" } = Astro.props;
       ---

       <!doctype html>
       <html lang="en" class="dark">
         <head>
           <meta charset="UTF-8" />
           <meta name="viewport" content="width=device-width, initial-scale=1.0" />
           <meta name="description" content={description} />
           <title>{title}</title>
           <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
           <style>
             html { background-color: #0a0a0f; color: #f5f5f5; }
           </style>
         </head>
         <body class="min-h-screen bg-background font-sans text-foreground antialiased">
           <slot />
         </body>
       </html>
       ```
       Per D-07 (class="dark" hardcoded), D-08 (inline style for FOUC prevention), D-10/D-11 (font imports).
       Font imports in frontmatter so Astro bundles them at build time (Pitfall 4 prevention).

    3. Create `src/pages/index.astro` -- a minimal proof-of-concept page that verifies the build pipeline works. This is a temporary page that Phase 2 will replace:
       ```astro
       ---
       import Layout from "../layouts/Layout.astro";
       ---

       <Layout title="Russell Moore — Engineering Leader & Builder">
         <main class="mx-auto max-w-4xl px-6 py-24">
           <h1 class="text-4xl font-bold text-foreground">Russell Moore</h1>
           <p class="mt-4 text-lg text-muted">Engineering Leader & Builder</p>
         </main>
       </Layout>
       ```
       This minimal page proves: Astro builds, Layout works, Tailwind classes apply, dark theme renders, fonts load. Content collection rendering is added in Plan 02.

    4. Ensure directory structure: `src/styles/`, `src/layouts/`, `src/pages/` all exist before creating files.
